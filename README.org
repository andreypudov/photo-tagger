* Overview
photo-tagger is a small command line utility that writes the metadata a photograph needs before it is published.
It sends each image to an OpenAI vision model and collects a title, a description, a keyword list and a category into a single JSON file.
A second script, =tags_export.py=, converts that JSON file into the upload files destinations expect, such as the Adobe Stock CSV, without calling the API again.

The same photograph is described differently depending on where it goes, so the tool writes for a chosen target: a microstock listing that has to be found through search, or a gallery wall label that has to be read in front of the print.

* Features
- Titles, descriptions and keywords generated from the image itself
- Two writing targets: =stock= for microstock marketplaces, =gallery= for museum and exhibition labels
- Batch processing of files or whole directories into one JSON document, optionally with concurrent requests
- A category for every photo from photo-tagger's own list, mapped to each stock site's categories on export
- Album location that the model uses in titles and keywords, refined to a recognizable landmark or site when it is certain, or an explicit =--no-location= for studio and product work
- Export of a JSON document into destination specific files, currently the Adobe Stock metadata CSV, as often as needed without new API calls
- Any vision capable OpenAI model, chosen per run or through an environment variable
- EXIF context (camera, lens, exposure, coordinates) forwarded to the model
- Structured JSON responses validated and normalized against the target limits
- A failing photo never aborts the run; its error is recorded alongside the results

* Usage
Tagging and export are two steps.
=photo_tagger.py= sends the photos to the API once and writes everything into a JSON document; =tags_export.py= turns that document into as many destination files as needed, without calling the API again.

Tag an album shot in one place for microstock, so that titles and keywords can name it:

#+begin_src bash
python photo_tagger.py -t stock -l "Madeira, Portugal" -o madeira.json ./madeira
#+end_src

Convert the result into an Adobe Stock metadata CSV:

#+begin_src bash
python tags_export.py -f adobe-stock -o madeira.csv madeira.json
#+end_src

Tag studio photos, which have no meaningful location, as exhibition wall labels:

#+begin_src bash
python photo_tagger.py -t gallery --no-location -o labels.json portrait.jpg still.tif
#+end_src

Print the result instead of writing a file:

#+begin_src bash
python photo_tagger.py -t stock --no-location -o - photo.jpg
#+end_src

Re-tag an album four photos at a time with a different model, replacing the previous result:

#+begin_src bash
python photo_tagger.py -t stock -l "Lisbon, Portugal" -o lisbon.json --model gpt-4.1 --jobs 4 --force ./lisbon
#+end_src

** Tagging Options
=python photo_tagger.py -t TARGET -o PATH (-l PLACE | --no-location) [options] FILE ...=

*** Required
| Option             | Description                                                                                      |
|--------------------+--------------------------------------------------------------------------------------------------|
| =FILE ...=         | Photos to tag, or directories containing photos                                                  |
| =-t=, =--target=   | =stock= or =gallery=                                                                             |
| =-o=, =--output=   | JSON file to write, or =-= for standard output; an existing file is only replaced with =--force= |
| =-l=, =--location= | Where the whole photo set was taken, e.g. ="Lisbon, Portugal"=                                   |
| =--no-location=    | The photo set has no meaningful location; use instead of =--location=                            |

Exactly one of =--location= and =--no-location= has to be given, so that every run decides about the location on purpose.

*** Optional
| Option            | Description                                                                           |
|-------------------+---------------------------------------------------------------------------------------|
| =-m=, =--model=   | Vision capable OpenAI model, overrides =PHOTO_TAGGER_MODEL= (default: =gpt-4.1-mini=) |
| =--detail=        | Image detail sent to the model: =low=, =high= or =auto= (default: =high=)             |
| =-j=, =--jobs=    | Number of photos processed concurrently (default: =1=)                                |
| =--api-key=       | API key, overrides =OPENAI_API_KEY=                                                   |
| =--max-dimension= | Longest edge of the image sent to the model (default: =1024=)                         |
| =--no-exif=       | Do not read EXIF metadata from the photos                                             |
| =--timeout=       | Per request timeout in seconds (default: =60=)                                        |
| =--retries=       | Automatic retries on transient API failures (default: =3=)                            |
| =--indent=        | Indentation of the generated JSON (default: =2=)                                      |
| =--force=         | Replace the output file if it already exists                                          |
| =-q=, =--quiet=   | Do not print progress information                                                     |
| =-h=, =--help=    | Show the help message and exit                                                        |
| =-v=, =--version= | Show the version and exit                                                             |

The model has to accept image input and structured JSON output.
=--detail low= is considerably cheaper and faster, at the cost of fine detail such as small text or distant subjects.
Raise =--jobs= to speed up large batches; requests that hit the account rate limit are retried automatically.
The tagging document is the result of paid API calls, so an existing output file is never replaced without =--force=; the check happens before any photo is sent.

Exit codes: =0= when every photo was tagged, =1= when at least one photo failed or the API was unreachable, =2= on invalid arguments, unreadable files or an existing output file, =130= on interrupt.
A rejected API key or an unknown model stops the run at the first photo instead of failing every photo in turn.

*** Optional

* Targets
** stock
Written for buyers who arrive through a search box.
Titles are literal and name the subject, the action and the setting; descriptions add the context that helps judge usage; keywords are lower case, ordered by relevance, and capped at 49 entries.

** gallery
Written the way a photograph is presented on display in a museum or an exhibition.
The title is an artwork title rather than a search phrase, and the description is a single sentence of no more than twenty words about the content of the photograph.
The whole series is imagined hanging in one exhibition room, so each description points to what distinguishes its photograph from the others rather than restating the theme they share.
Keywords stay curatorial, covering genre, motif and formal qualities.

* Output Format
The tool writes one JSON document per run:

#+begin_src json
{
  "target": "gallery",
  "model": "gpt-4.1-mini",
  "generated_at": "2026-09-22T08:16:41+00:00",
  "photos": [
    {
      "file": "samples/lighthouse.jpg",
      "filename": "lighthouse.jpg",
      "title": "Keeper of the Morning Tide",
      "description": "A lighthouse stands on a granite headland as the first morning light reaches the rock.",
      "keywords": ["seascape", "solitude", "morning light", "cornwall", "england"],
      "category": {"primary": "landmark", "secondary": "seascape"},
      "location": {"given": "Cornwall, England", "detected": "Godrevy Lighthouse"}
    }
  ]
}
#+end_src

=category= holds the =primary= category of the photo and an optional =secondary= one, or =null=, both from the list in [[*Categories][Categories]].
=location= is present only when =--location= was given: =given= is the value passed on the command line, =detected= the more specific place the model recognized in the photo, or =null=.
An =errors= array is added when a photo could not be tagged, listing the file and the reason.

* Categories
Every stock site has its own category list, and the lists do not line up.
photo-tagger therefore uses one list of its own that is at least as fine-grained as every site's list: each of its categories maps to exactly one category of each site.
The model picks from this list once, and every export format translates the choice into its site's category.
A new site only needs a new mapping, so documents that were already tagged export to it without calling the API again.

The model sets =primary= to the category of the main subject and =secondary= to a second category only when it clearly applies as well.
Export formats use =primary=; =secondary= is kept for sites that accept a second category.

When a photo fits more than one category, the model follows these rules, so that similar photos of an album end up in the same category:
- A recognizable landmark is =landmark=, even when it is also architecture or a travel subject.
- =people= when a person is the subject, =lifestyle= when the activity or scene matters more than who is in it.
- =travel= only when tourism itself is shown, such as travellers, luggage or sightseeing; a place on its own is =landscape=, =cityscape= or =landmark=.
- Religious buildings are =landmark= or =architecture=; =culture_religion= is for ceremonies, rituals, traditions and art.
- =backgrounds_textures= when there is no distinct subject.
- =emotions_concepts= only when a feeling or an idea is clearly the point of the photograph.

The list lives in =tagger/categories.py= and each site's mapping in =tagger/export.py=.
Splitting a category later means that the photos in it have to be tagged again, so it is worth keeping the list fine-grained.

* Location
Photos are usually tagged one album at a time, and an album is usually shot in one place: a city, an island or a single site.
=--location= describes that place for the whole run and is treated as a fact.
Write it from specific to general and end with the country, so that every level a buyer might search is available:

| Album         | =--location=                      |
|---------------+-----------------------------------|
| Whole city    | ="Lisbon, Portugal"=              |
| Island        | ="Madeira, Portugal"=             |
| Specific site | ="Pena Palace, Sintra, Portugal"= |

For every photo the model:
- names a more specific place in =detected= only when a landmark, building, site or natural feature within the given location is clearly visible and unmistakable, and leaves it =null= for generic scenes or whenever it is not certain;
- never contradicts the given location, which is always kept unchanged in =given=;
- adds the place names after the subject keywords, at most four location keywords in total;
- names the place in the title only when the place itself is the subject, such as a landmark, cityscape or landscape.

With =--no-location= no place names are used.
The location applies to every photo of the run, so photos from a day trip elsewhere belong in a separate run with their own location.

* Export Formats
** adobe-stock
A CSV for the Adobe Stock metadata upload dialog, one row per photo:

#+begin_src csv
Filename,Title,Keywords,Category,Releases
lighthouse.jpg,Lighthouse on rocky coastline at sunrise with calm sea,"lighthouse, coastline, sunrise, rocky shore",11,
#+end_src

| Column   | Content                                                     |
|----------+-------------------------------------------------------------|
| Filename | File name of the photo, including the extension             |
| Title    | The generated title, at most 200 characters                 |
| Keywords | Comma separated keywords ordered by relevance, at most 49   |
| Category | Adobe Stock category code, 1 to 21, mapped from =primary=   |
| Releases | Always empty                                                |

The description is not part of this format.
Adobe Stock matches rows to uploads by file name alone, so a document in which two photos share a file name is rejected.
Photos without a category, for example from documents written before the category list was added, are exported with an empty =Category= cell and listed in a warning.
=samples/tags.stock.json= and =samples/tags.gallery.json= are illustrative documents showing the shape of both targets.

* Useful Scripts
- =scripts/photo_resize.sh= downscales a folder of photos into a working directory before tagging.
- =scripts/photo_embed_metadata.sh= writes a generated JSON document back into the photo files as IPTC, XMP and EXIF tags using =exiftool=.

* How It Works
The program:
1. Expands the given files and directories into a stable list of photos.
2. Decodes each image, reads a small subset of its EXIF data, rotates it upright according to its EXIF orientation and encodes a downscaled JPEG as a data URL.
3. Builds a target specific system prompt and asks the model for a strict JSON response.
4. Rejects refusals and truncated responses, then normalizes the result: whitespace collapsed, titles and descriptions truncated to the target limits, keywords lower cased, deduplicated and capped.
5. Collects every photo into one document and writes it to disk.
6. =tags_export.py= later reads that document and writes any export format from it, without contacting the API.

Only the downscaled copy is sent to the API; the original files are never modified.
